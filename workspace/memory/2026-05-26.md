- Investigated GitHub issue #4245: `nemoclaw <sandbox> shields up/down` failed on macOS OpenShell VM driver by attempting `docker exec openshell-cluster-nemoclaw kubectl exec` even though VM-driver gateways have no legacy K3s cluster container.
- Updated `/root/.openclaw/workspace/projects/nemoclaw/upstream/src/lib/shields/index.ts` to detect `openshellDriver: "vm"` before any policy/state mutation or docker/kubectl probing and fail with an explicit unsupported-backend message instead of `No such container: openshell-cluster-nemoclaw`.
- Added regression coverage in `test/repro-2681-group-writable.test.ts` proving VM-driver shields reject before calling Docker probes.
- Verified with `npm run build:cli`, `npx vitest run test/repro-2681-group-writable.test.ts src/lib/shields/index.test.ts`, and a manual fake-HOME CLI smoke (`node bin/nemoclaw.js alpha shields up`) confirming exit 1 with no fake docker invocation.
- Note: this is a safe guard, not full macOS VM shields support; OpenShell currently exposes no privileged host-side root exec backend for VM sandboxes, so true support needs an upstream OpenShell capability.
