1. 一句话结论

借鉴开源框架普遍采用的「数据层 / 信号层 / 风控层 / 回测层 / 展示层」彻底解耦的事件驱动架构，可以用较小成本搭建一个「输入股票代码 → 输出结构化波段研究信号（区间、止损、仓位、触发条件、风险提示）」的工具；**其核心价值在于把规则透明化、可回测、可解释，而非预测涨跌或承诺盈利**。

3. 共同设计精华

这些项目尽管定位不同，但收敛出一套高度一致的设计原则，值得直接吸收：

1. **彻底分层解耦**：数据源、指标/特征、策略/信号、撮合/执行、风控、绩效分析各自独立，可单独替换与测试。

2. **事件驱动 + 数据回放统一**：回测与实盘共用同一套「数据驱动 → 信号 → 下单」流程，保证「回测即生产」的一致性，避免两套逻辑产生偏差。

3. **指标/因子可组合、可复用**：指标作为独立单元，策略只是指标的组合与判定规则，便于复用与单测。

4. **配置驱动 + 参数与代码分离**：止损、ROI、仓位、风控阈值等用配置表达（freqtrade 的 minimal_roi/stoploss 是典型），便于扫描与审计。

5. **回测严谨性优先**：内建对前视偏差(look-ahead)、未来函数、滑点、手续费、成交可行性的处理；强调用「下一根K线开盘」等方式避免用未来数据。

6. **绩效与可解释报告标准化**：统一的 analyzer / tearsheet 输出（收益、回撤、夏普、胜率、盈亏比），让结果可比较、可审计。

7. **参数优化与稳健性意识**：提供超参优化的同时，社区普遍警示过拟合，强调样本外验证、walk-forward。

8. **可观测与可控制**：日志、状态、WebUI/CLI/通知，使系统行为对人透明、可干预。

4. 波段交易建议应使用的指标/特征

波段（swing，持仓数日到数周）关注「中期趋势 + 阶段超买超卖 + 关键价位 + 量能确认」。建议分类组合，避免单指标决策：

**趋势类（定方向）**

  • 均线系统：MA/EMA（如 20/50/200），均线多空排列、金叉死叉
  • MACD：DIF/DEA 与柱状能量，判断中期动能拐点
  • ADX：趋势强度过滤（弱趋势时降低信号权重）

**动量/超买超卖类（定时机）**

  • RSI（14）：超买/超卖与背离
  • 随机指标 KD（Stochastic）
  • 价格相对近期高低点位置（如距 N 日高点的回撤幅度）

**波动率类（定区间与止损）**

  • ATR：用于设置止损距离、买入区间宽度与仓位归一化
  • 布林带：通道位置、带宽收缩/扩张（突破前兆）

**量能类（确认）**

  • 成交量均量比、放量/缩量
  • OBV / 量价配合度

**结构/位置类（定关键价位）**

  • 近期支撑/阻力、前高前低
  • 回调到关键均线或斐波那契回撤位（38.2% / 50% / 61.8%）

**特征工程建议**：所有指标尽量归一化（如用 ATR 做尺度），并加入「多周期一致性」特征（日线 + 周线方向是否同向），降低单周期噪声。**严禁使用未来数据**（如用当日收盘后才知道的值生成当日信号）。

5. 风控规则

风控应是**硬约束**，优先级高于信号层，且全部以配置表达、可回测：

1. **单笔止损**：基于 ATR（如入场价 − k×ATR，k 取 1.5~3）或固定百分比，二者取更保守者；止损必须在入场前确定。

2. **单笔最大风险敞口**：单笔亏损不超过总资金的固定比例（如 1%~2%），由此**反推仓位**（见下）。

3. **仓位计算（波动率/风险归一化）**：仓位 = (账户资金 × 单笔风险比例) ÷ (入场价 − 止损价)；高波动标的自动减仓。

4. **组合层限制**：单标的占比上限、行业/板块集中度上限、同时持仓数量上限、总仓位上限。

5. **回撤熔断**：账户回撤达阈值（如 −10%/−20%）时降低仓位或暂停开新仓。

6. **趋势/环境过滤**：大盘或个股处于明确弱势/高波动异常时，禁止逆势开仓。

7. **流动性与可交易性**：剔除停牌、低流动性、即将退市、价格异常（涨跌停无法成交）标的。

8. **止盈/移动止损**：分批止盈或跟踪止损（trailing stop），锁定波段利润。

9. **信号有效期**：每条建议设置有效窗口（如 N 个交易日），过期作废，避免用陈旧信号。

10. **去过拟合纪律**：参数须经样本外 / walk-forward 验证，禁止用全样本最优参数对外输出。

6. MVP 架构

整体遵循各框架的分层思想，每层职责单一、接口清晰、可独立测试。

输入  →  数据层  →  信号层  →  评分层  →  风控层  →  解释层  →  输出
                          �‖ 共用同一流程 �g
                        回测层（历史回放 + 绩效评估）

**① 输入层 Input**

  • 入参：股票代码（含市场）、可选时间窗口、可选风险偏好档位（仅影响仓位/止损参数预设，不构成个性化建议）。
  • 校验：代码合法性、市场归属、是否可交易（停牌/退市过滤）。

**② 数据层 Data**

  • 行情获取（日线为主、周线辅助）、复权处理、交易日历、停牌补齐。
  • 标准化为统一 OHLCV 数据结构（借鉴 Qlib 的标准化数据集 / zipline 的 calendar）。
  • 缓存与数据质量校验（缺失、异常值、跳空检测）。

**③ 信号层 Signal**

  • 指标计算（第 4 节指标），各指标为可复用单元（借鉴 backtrader 指标对象）。
  • 规则判定：趋势方向 + 时机条件 + 量能确认 + 结构位置，输出多个原子信号。

**④ 评分层 Score**

  • 将多信号加权聚合为综合评分（如 0~100）与方向（偏多/中性/偏空）。
  • 加入多周期一致性、信号冲突惩罚；输出置信度（仅表达规则强弱，非概率收益）。

**⑤ 风控层 Risk**

  • 应用第 5 节硬约束：计算止损价、仓位、检查组合/流动性限制；不通过则降级或拒绝出信号。

**⑥ 解释层 Explain**

  • 生成「为什么给出该信号」的可读理由：哪些指标触发、关键价位、风险点；保证透明可审计。

**⑦ 回测层 Backtest**

  • 与信号/风控层**共用同一逻辑**进行历史回放（事件驱动）；计入手续费、滑点、成交可行性。
  • 输出标准绩效报告：累计收益、最大回撤、夏普、胜率、盈亏比、平均持仓周期。
  • 支持参数扫描（可借 vectorbt 思路）+ 样本外 / walk-forward 验证。

**⑧ 输出层 Output**

  • 结构化数据（JSON）+ 人类可读模板（见第 7 节）；附回测统计与免责声明。

8. 不应该做什么

  • ❌ **不承诺收益**、不给出「稳赚 / 必涨 / 目标价一定到」等表述。
  • ❌ **不提供个性化投资建议**：不根据用户身家、负债、风险承受能力定制操作指令。
  • ❌ **不使用未来函数 / 前视偏差**：不得用当根 K 线收盘后才知道的数据生成同期信号。
  • ❌ **不展示无样本外验证的「最优参数」回测曲线**作为效果证明（过拟合陷阱）。
  • ❌ **不忽略交易成本**：回测必须计手续费、滑点、停牌与成交可行性。
  • ❌ **不做自动下单/实盘执行**（MVP 阶段），避免越过「研究工具」边界与合规风险。
  • ❌ **不替代专业意见**：不暗示工具可替代持牌投顾或正规研究。
  • ❌ **不数据造假**：回测与统计如实呈现，包括亏损与失败案例。
  • ❌ 不对外宣传时省略免责声明。

9. 下一步实现计划

**阶段 0：原型（1~2 周）**

  • 用 **backtesting.py** 起步，单标的、3~4 个指标，跑通「输入代码 → 信号 → 文本输出」闭环。
  • 确定数据源与复权/交易日历方案，搭建数据缓存与质量校验。

**阶段 1：分层重构（2~4 周）**

  • 按第 6 节拆分数据/信号/评分/风控/解释/回测/输出七层，定义清晰接口。
  • 风控以**配置表**表达（仿 freqtrade 的 stoploss/ROI/仓位配置）。
  • 引入标准绩效报告（仿 zipline tearsheet）。

**阶段 2：严谨回测与稳健性（3~5 周）**

  • 引入手续费/滑点/成交可行性模型。
  • 用 **vectorbt** 做参数扫描，配合 **walk-forward / 样本外验证**，建立过拟合检测纪律。
  • 多标的批量回测与结果可比报告。

**阶段 3：特征与可解释增强（按需）**

  • 借鉴 **Qlib** 的特征/因子工程与数据集管理，逐步引入更多特征与（可选）ML 评分模型，但保留可解释规则作为主干。

**阶段 4：交付形态**

  • CLI 优先，再做轻量 WebUI / API（仿 freqtrade、vn.py 的可观测与控制层）。
  • 全链路日志、信号留痕与回放，确保每条对外信号可审计。
  • 完成合规审查：所有输出强制附带免责声明与「研究用途」标识。

**贯穿全程的纪律**：回测即生产共用逻辑、禁未来函数、计成本、样本外验证、如实呈现、永不承诺收益。
